## structure

<ReferenceMeta type="TreeNode<T>[]" required />

`structure` is the hierarchy Direactree renders and the only source of truth for it. Root items are array entries; nested items live in a folder's `children`.

```ts
interface TreeNode<T = unknown> {
  /** Must be unique across the whole tree. */
  id: string;
  name: string;
  type: "file" | "folder";
  children?: TreeNode<T>[];
  /** First open state, read once when the tree mounts. */
  isExpanded?: boolean;
  /** Not-yet-loaded children, used with onLoadChildren. */
  hasChildren?: boolean;
  /** Turns every permission off. */
  locked?: boolean;
  /** Per-node permissions. A missing key counts as allowed. */
  permissions?: Partial<NodePermissions>;
  /** Your own data, passed through untouched. */
  data?: T;
}
```

`children` is optional because files have none and empty folders may leave it out. The component never copies or mutates this array: it only reports what the user asked for, and changes when you pass a new `structure`. When a node leaves `structure`, its selection and any editor open on it are cleared.

<Callout tone="warning" title="Use stable, unique ids">
  Selection, editing, and moves identify nodes by id. Ids must be unique across the whole tree, not only among siblings. Avoid array indexes when nodes may move.
</Callout>

## Display and interaction

### indent

<ReferenceMeta type="number" defaultValue="20" />

The space added per level, from `8` to `50`. Values outside the range are clamped, with a console warning. It sets the `--direactree-indent` token.

```tsx
<Direactree structure={structure} indent={28} />
```

<IndentDemo />

### isAllExpanded

<ReferenceMeta type="boolean" defaultValue="false" />

While `true`, every folder is open, including folders added later, and folders cannot be closed. Changing it to `false` closes every folder. For finer control use [`expandedIds`](/docs/direactree/navigation#open-folders).

<ExpandedDemo />

### allowDragAndDrop and allowReorder

<ReferenceMeta type="boolean" defaultValue="true / false" />

`allowDragAndDrop` turns dragging on or off. Dragging also needs `onNodeMove`, follows the `move` and `drop` permissions, and pauses while a request is pending.

`allowReorder` lets a drop land before or after a row as well as inside a folder: the top quarter of a folder row means before, the bottom quarter after, and the middle inside. A file row splits in half. A line or a dashed box shows the result.

```tsx
const tree = useDireactree(structure);

<Direactree structure={tree.structure} onNodeMove={tree.move} allowReorder />
```

<DragAndDropDemo />

### showToolbox

<ReferenceMeta type="boolean" defaultValue="true" />

Shows the create-folder, create-file, rename, and delete buttons. Each is enabled only when it can do something:

| Button | Enabled when |
| --- | --- |
| Create folder, Create file | `onSave` is set, and nothing or a folder with `createChild` is selected. |
| Rename | `onSave` is set and the selected node allows `rename`. |
| Delete | `onDelete` is set and the selected node allows `delete`. |

All are disabled while a request is pending. A read-only tree needs no handlers at all.

### toolboxSticky

<ReferenceMeta type="boolean" defaultValue="false" />

Keeps the toolbox at the top while the tree's scroll container moves. Use it for tall trees in a fixed-height panel.

### toolboxIcons

<ReferenceMeta type="ToolboxIcons" />

Replaces any built-in icon with a `ReactNode`. The defaults are SVG icons that follow the text color. Each button keeps its accessible name and tooltip from `messages`, so your icons can be decorative.

```ts
interface ToolboxIcons {
  createFolder?: React.ReactNode;
```

### confirmDelete

<ReferenceMeta type="boolean" defaultValue="false" />

The delete action opens a confirmation under the row, and `onDelete` runs only after the user confirms.

- The popover floats over the tree and opens above the row when there is no room below.
- **Cancel** gets focus. Escape or Cancel closes it, and focus returns to the delete button.
- While a returned Promise is pending, both buttons are disabled and the confirm button reads "Deleting…". A rejection keeps it open with the error.

### style

<ReferenceMeta type="DireactreeStyle" />

Inline styles on the root, applied after the theme's `color-scheme`. The type accepts `--direactree-*` tokens without a cast. Use `light-dark()` to give each theme its own color.

```tsx
<Direactree
```

## Event callbacks

Callbacks report what the user did or asked for. Your application decides whether to update state, call an API, or refuse.

`NodePath` describes a node and its ancestors through `parent`. A root node has `parent: null`.

```ts
type NodePath = {
  name: string;
  id: string;
  type: "file" | "folder";
  parent: NodePath | null;
};
```

### onSelectedNodeChange

<ReferenceMeta type="(node: NodePath | null) => void" />

Called when the selected node changes or the selection becomes empty, and again when the selected node is renamed or moved, because its path changed. The selection clears when the user clicks outside the tree or the node leaves `structure`. When a folder closes over the selected node, selection moves to that folder.

In multiple selection mode it reports the focused row. `onSelectionChange(ids, nodes)` reports every selected id. See [Selection](/docs/direactree/navigation#selection).

<SelectionCallbackDemo />

### onNodeActivate

<ReferenceMeta type="(node: TreeNode<T>, path: NodePath) => void" />

Called on a double click and on <kbd>Enter</kbd>. On a folder, the folder also opens or closes. Use it to open a file.

### onNodeMove

<ReferenceMeta type="(node: TreeNode<T>, target: TreeNode<T>, info: MoveInfo) => void | Promise<void>" />

Called when a node is dropped on a valid place. `target` is the folder for an `inside` drop, or the row the node lands next to for `before` and `after`. `info` says exactly where it goes:

```ts
interface MoveInfo {
  position: "inside" | "before" | "after";
  parentId: string | null; // the new folder, null for the root
  index: number;           // among the new folder's children, not counting the moved node
}
```

```tsx
async function handleNodeMove(node: TreeNode, target: TreeNode, info: MoveInfo) {
  await api.move(node.id, info.parentId, info.index);
  tree.move(node, target, info);
}
```

It is **not called** when the node is dropped on itself or into its own descendant, on a file without `allowReorder`, where it already is, where a node with the same name exists, or where permissions forbid it. The destination folder opens on drop.

### Toolbox action callbacks

<ReferenceMeta type="NodePath callbacks" />

```ts
onCreateFolder?: (parentNode: NodePath | null) => void;
onCreateFile?: (parentNode: NodePath | null) => void;
onRename?: (node: NodePath) => void;
onDelete?: (node: NodePath) => void | Promise<void>;
```

`onCreateFolder`, `onCreateFile`, and `onRename` fire when the name editor opens; the parent folder opens so the editor is visible. The create or rename itself arrives in `onSave`. `null` means the root. `onDelete` receives the node to delete; with `confirmDelete`, only after the user confirms.

<ToolboxCallbacksDemo />

### onSave

<ReferenceMeta type="(saveProps: SaveProps) => void | Promise<void>" />

Called when the user confirms a valid name with Save or <kbd>Enter</kbd>. Save stays disabled while the name is empty, unchanged, or fails a [name check](/docs/direactree/validation#name-checks).

```ts
interface SaveProps {
  newName: string;              // trimmed
  selectedNode: NodePath | null; // the parent for a create, the node for a rename
  actionType: "create" | "edit";
  createType?: "folder" | "file";
}
```

`useDireactree().save` applies it directly, and `applySave(nodes, props)` does the same as a pure function.

<SaveCallbackDemo />

### onExpandedChange and onSearchChange

<ReferenceMeta type="(ids: string[]) => void  ·  (term: string) => void" />

`onExpandedChange` receives every open folder id whenever one opens or closes, including from the ref handle. `onSearchChange` receives what is typed into the built-in search field.

### onLoadChildren

<ReferenceMeta type="(node: TreeNode<T>) => void | Promise<unknown>" />

Called once for a folder with `hasChildren: true` and no `children`, the first time it is open. Return the Promise so the loading row stays until it settles. See [Lazy loading](/docs/direactree/large-trees#lazy-loading).

### Async callbacks and errors

`onSave`, `onDelete`, `onNodeMove`, and `onLoadChildren` may return a Promise. Direactree then waits:

- While it is pending, the toolbox, editor, and confirmation buttons are disabled and dragging pauses. Only one save, delete, or move runs at a time.
- When it resolves, the editor or confirmation closes.
- When it rejects or the handler throws, the editor or confirmation stays open with the typed name and the error's `message` (or `messages.actionFailed`). A failed load shows the error and Retry in the folder.
- `onActionError(error, action)` is called with `"save"`, `"delete"`, `"move"`, or `"load"`.

```tsx
<Direactree
  structure={tree.structure}
  onSave={handleSave}
  onActionError={(error, action) => reportError(action, error)}
/>
```

A failed move has no editor to show its error in, so use `onActionError` to tell the user.

## Ref handle

Pass a `ref` to call these methods. See [Reveal from code](/docs/direactree/navigation#reveal-from-code) for a live demo.

```ts
interface DireactreeHandle {
  revealNode(id: string, options?: { select?: boolean; focus?: boolean; block?: "start" | "center" | "end" | "nearest" }): boolean;
  expand(id: string): void;
  collapse(id: string): void;
  expandAll(): void;
  collapseAll(): void;
  select(id: string | null): void;
  focus(): void;
  getSelectedIds(): string[];
  getExpandedIds(): string[];
}
```

```tsx
const ref = useRef<DireactreeHandle>(null);
<Direactree ref={ref} structure={structure} />;
```

## Complete types

```ts
type NodeType = "file" | "folder";

interface NodePermissions {
  rename: boolean;
  delete: boolean;
  move: boolean;
  drop: boolean;
  createChild: boolean;
}

interface ToolboxAction {
  id: string;
  label: string;
  icon: React.ReactNode;
  disabled?: boolean | ((selectedNode: NodePath | null, selectedIds: string[]) => boolean);
  onClick: (selectedNode: NodePath | null, selectedIds: string[]) => void;
}

type ContextMenuEntry<T = unknown> =
  | {
      id: string;
      label: React.ReactNode;
      icon?: React.ReactNode;
      disabled?: boolean;
      danger?: boolean;
      onSelect: (node: TreeNode<T>, path: NodePath) => void;
    }
  | "separator";

interface RowRenderState {
  expanded: boolean;
  selected: boolean;
  depth: number;
}

interface LabelRenderState extends RowRenderState {
  term: string;
  highlighted: React.ReactNode;
}

interface VirtualizedOptions {
  rowHeight?: number;
  overscan?: number;
  height?: number | string;
}

type DireactreeTheme = "system" | "light" | "dark";
type DireactreeAppearance = "plain" | "card";
type DireactreeDensity = "comfortable" | "compact";
type DireactreeMutation = "save" | "delete" | "move" | "load";
type DropPosition = "inside" | "before" | "after";
type DireactreeStyle = React.CSSProperties & { [token: `--direactree-${string}`]: string | number | undefined };

type DireactreeSlot =
  | "root" | "toolbox" | "toolboxButton" | "search" | "viewport" | "list"
  | "row" | "item" | "toggle" | "icon" | "label" | "badge"
  | "editor" | "menu" | "menuItem" | "confirm";
```
