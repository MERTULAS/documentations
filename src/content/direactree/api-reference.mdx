# Props & callbacks

<p className="lead">A complete reference for every Direactree prop, callback payload, default value, type, behavior rule, and common use case.</p>

## Props overview

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `structure` | `TreeNode[]` | Required | Controlled tree rendered by the component. |
| `className` | `string` | — | Adds a class to the component root. |
| `style` | `React.CSSProperties` | — | Inline styles merged onto the root, after the theme `color-scheme`. |
| `theme` | `"system" \| "light" \| "dark"` | `"system"` | Built-in color theme. |
| `indent` | `number` | `20` | Horizontal offset between hierarchy levels. |
| `showToolbox` | `boolean` | `true` | Shows create, rename, and delete controls. |
| `toolboxIcons` | `ToolboxIcons` | Built-in icons | Replaces individual toolbox icons. |
| `toolboxSticky` | `boolean` | `false` | Keeps the toolbox visible while its container scrolls. |
| `allowDragAndDrop` | `boolean` | `true` | Enables node movement. Also needs `onNodeMove`. |
| `isAllExpanded` | `boolean` | `false` | Keeps every folder open while `true`. |
| `confirmDelete` | `boolean` | `false` | Asks for confirmation before `onDelete`. |
| `messages` | `Partial<DireactreeMessages>` | English copy | Replaces built-in labels and messages. |
| `onCreateFolder` | `(parent: NodePath \| null) => void` | — | The create-folder editor opened. |
| `onCreateFile` | `(parent: NodePath \| null) => void` | — | The create-file editor opened. |
| `onRename` | `(node: NodePath) => void` | — | The rename editor opened. |
| `onSave` | `(props: SaveProps) => void \| Promise<void>` | — | A create or rename was confirmed. |
| `onDelete` | `(node: NodePath) => void \| Promise<void>` | — | A delete was requested (and confirmed, if `confirmDelete`). |
| `onNodeMove` | `(node: TreeNode, target: TreeNode) => void \| Promise<void>` | — | A valid drag-and-drop move was requested. |
| `onSelectedNodeChange` | `(node: NodePath \| null) => void` | — | Selection changed. |
| `onActionError` | `(error: unknown, action: DireactreeMutation) => void` | — | A save, delete, or move threw or rejected. |

<Callout title="Handlers enable the controls">
  The toolbox only offers what your application can handle. Create and rename stay disabled without `onSave`, delete stays disabled without `onDelete`, and nodes cannot be dragged without `onNodeMove`.
</Callout>

## structure

<ReferenceMeta type="TreeNode[]" required />

`structure` is the hierarchy rendered by Direactree, and the only source of truth for it. Root items are array entries; nested items live in a folder's `children` array.

```ts
interface TreeNode {
  /** Must be unique across the whole tree. */
  id: string;
  name: string;
  type: "file" | "folder";
  children?: TreeNode[];
  /** Initial open state, read once when the tree mounts. */
  isExpanded?: boolean;
}
```

Example structure:

```ts
const structure: TreeNode[] = [
  {
    id: "0",
    name: "C:/",
    type: "folder",
    children: [
      {
        id: "1",
        name: "Users",
        type: "folder",
        children: [
          {
            id: "2",
            name: "John Doe",
            type: "folder",
            children: [
              {
                id: "3",
                name: "Documents",
                type: "folder",
                children: [
                  { id: "4", name: "sample.tsx", type: "file" },
                ],
              },
              { id: "5", name: "logs.txt", type: "file" },
            ],
          },
        ],
      },
    ],
  },
];

<Direactree structure={structure} />;
```

`children` is optional because files do not contain nodes and empty folders may omit it. Supplying `children: []` for folders is also valid.

The component never copies or mutates this array. Creating, renaming, deleting, or moving a node only calls your handler. The tree changes when you pass a new `structure`. Direactree keeps UI state only: selection, which folders are open, the open editor or delete confirmation, and pending and error state.

`isExpanded` is read once, when the tree mounts. After that the user opens and closes folders and Direactree remembers it. When a node leaves `structure`, its selection and any editor open on it are cleared.

<Callout tone="warning" title="Use stable, unique IDs">
  Selection, editing, and moves identify nodes by ID. IDs must be unique across the whole tree, not only among siblings. Avoid array indexes when nodes may move.
</Callout>

## Display and interaction

### indent

<ReferenceMeta type="number" defaultValue="20" />

Controls the horizontal indentation between tree levels. The accepted range is `8`–`50`:

- Values below `8` are normalized to `8`.
- Values above `50` are normalized to `50`.

A console warning is logged when a value is normalized.

```tsx
<Direactree structure={structure} indent={28} />
```

Use a smaller value in narrow sidebars and a larger value when hierarchy depth should be visually prominent.

<IndentDemo />

### isAllExpanded

<ReferenceMeta type="boolean" defaultValue="false" />

While `true`, every folder is open, including folders added to `structure` later, and folders cannot be collapsed. Changing it from `true` to `false` closes every folder.

```tsx
const [expandAll, setExpandAll] = useState(false);

<button onClick={() => setExpandAll((value) => !value)}>
  {expandAll ? "Collapse all" : "Expand all"}
</button>
<Direactree structure={structure} isAllExpanded={expandAll} />
```

Unlike in 0.1, the prop can change at any time. There is no need to remount the tree with a `key`.

<ExpandedDemo />

### allowDragAndDrop

<ReferenceMeta type="boolean" defaultValue="true" />

Enables or disables moving files and folders by dragging. Dragging also needs an `onNodeMove` handler, and is paused while a save, delete, or move is pending.

```tsx
<Direactree structure={structure} allowDragAndDrop={false} />
```

Set it to `false` for read-only explorers or when your backend does not support re-parenting. This setting does not hide the toolbox; use `showToolbox` separately.

<DragAndDropDemo />

### showToolbox

<ReferenceMeta type="boolean" defaultValue="true" />

Controls the built-in create-folder, create-file, rename, and delete buttons.

```tsx
<Direactree structure={structure} showToolbox={false} />
```

Each button is enabled only when it can do something:

| Button | Enabled when |
| --- | --- |
| Create folder, Create file | `onSave` is set, and the selection is a folder or nothing. |
| Rename | `onSave` is set and a node is selected. |
| Delete | `onDelete` is set and a node is selected. |

All four are disabled while a request is pending. To make a tree completely read-only, combine `showToolbox={false}` and `allowDragAndDrop={false}`, or omit the handlers.

<ToolboxVisibilityDemo />

### toolboxSticky

<ReferenceMeta type="boolean" defaultValue="false" />

Keeps the toolbox visible while the tree's scroll container moves.

```tsx
<div style={{ height: 320, overflow: "auto" }}>
  <Direactree
    structure={structure}
    toolboxSticky
    isAllExpanded
  />
</div>
```

Use it for tall trees inside a height-constrained panel. It has no visible effect when the surrounding content does not scroll.

<StickyToolboxDemo />

### toolboxIcons

<ReferenceMeta type="ToolboxIcons" />

Replaces any built-in toolbox icon with a `ReactNode`. Every field is optional, so icons can be changed individually.

```ts
interface ToolboxIcons {
  createFolder?: React.ReactNode;
  createFile?: React.ReactNode;
  rename?: React.ReactNode;
  delete?: React.ReactNode;
}
```

```tsx
const toolboxIcons = {
  createFolder: <FolderPlusIcon />,
  createFile: <FilePlusIcon />,
  rename: <EditIcon />,
  delete: <TrashIcon />,
};

<Direactree
  structure={structure}
  toolboxIcons={toolboxIcons}
/>;
```

Each button already has an accessible name and tooltip from `messages`, so icons can be decorative.

<ToolboxIconsDemo />

### confirmDelete

<ReferenceMeta type="boolean" defaultValue="false" />

When `true`, the delete button opens a confirmation popover under the selected row. `onDelete` is called only after the user confirms.

```tsx
<Direactree structure={structure} confirmDelete onDelete={handleDelete} />
```

- The popover floats over the tree and does not move the layout. It opens above the row when there is no room below.
- **Cancel** gets focus when it opens. Escape or Cancel closes it, and focus returns to the delete button.
- If `onDelete` returns a Promise, both buttons stay disabled and the confirm button reads "Deleting…" until it settles. A rejection keeps the popover open with the error message.

<ConfirmDeleteDemo />

### className

<ReferenceMeta type="string" />

Adds a custom class name to the Direactree root element.

```tsx
<Direactree structure={structure} className="project-explorer" />
```

Use it for spacing, sizing, and placement in your own layout. To change colors, set the [CSS variables](/docs/direactree/theming#css-variables) on that class.

## Theme and copy

### theme

<ReferenceMeta type={'"system" | "light" | "dark"'} defaultValue='"system"' />

Chooses the built-in palette. `"light"` and `"dark"` stay fixed. `"system"` follows the user's `prefers-color-scheme` setting.

```tsx
<Direactree structure={structure} theme="dark" />
```

The root gets a `data-direactree-theme` attribute and a matching `color-scheme`. See [Theming & accessibility](/docs/direactree/theming) for the CSS variables.

<ThemeDemo />

### style

<ReferenceMeta type="React.CSSProperties" />

Inline styles for the root element. They are applied after the theme's `color-scheme`, so they can override it or set CSS variables on this one tree.

```tsx
<Direactree
  structure={structure}
  style={{
    "--direactree-selected": "#fde68a",
    "--direactree-focus": "#b45309",
  } as React.CSSProperties}
/>
```

### messages

<ReferenceMeta type="Partial<DireactreeMessages>" />

Replaces the built-in English copy: button labels, tooltips, field labels, the delete confirmation, and the fallback error. Omitted keys keep the defaults. In `deleteTitle`, `{name}` is replaced with the node name.

```tsx
<Direactree
  structure={structure}
  messages={{
    delete: "Sil",
    cancel: "Vazgeç",
    deleteTitle: "{name} silinsin mi?",
  }}
/>
```

| Key | Default |
| --- | --- |
| `directoryTree` | Directory tree |
| `createFolder` | Create Folder |
| `createFile` | Create File |
| `rename` | Rename |
| `delete` | Delete |
| `save` | Save |
| `cancel` | Cancel |
| `newFolderName` | New folder name |
| `newFileName` | New file name |
| `newItemName` | New item name |
| `deleteTitle` | Delete \{name\}? |
| `deleteFolderDescription` | This folder and its contents will be deleted. |
| `deleteFileDescription` | This file will be deleted. |
| `deleting` | Deleting… |
| `confirmDelete` | Confirm delete |
| `actionFailed` | Something went wrong. |

The defaults are exported as `defaultDireactreeMessages`.

## Event callbacks

Callbacks report what the user did or asked for. Your application decides whether to update state, call an API, or reject the request.

`NodePath` is used by selection and toolbox callbacks:

```ts
type NodePath = {
  name: string;
  id: string;
  type: "file" | "folder";
  parent: NodePath | null;
};
```

Unlike `TreeNode`, `NodePath` describes ancestry through its recursive `parent` field. A root node has `parent: null`.

### onSelectedNodeChange

<ReferenceMeta type="(node: NodePath | null) => void" />

Called when the selected node changes, or when selection becomes empty. It is also called when the selected node is renamed or moved, because its path changed.

```tsx
const [selectedNode, setSelectedNode] = useState<NodePath | null>(null);

<Direactree
  structure={structure}
  onSelectedNodeChange={setSelectedNode}
/>;
```

Selection is cleared, with `null`, when the user clicks outside the tree or the node is removed from `structure`. If the selected node is hidden because a folder above it closed, selection moves to that folder.

<SelectionCallbackDemo />

### onNodeMove

<ReferenceMeta type="(sourceNode: TreeNode, targetNode: TreeNode) => void | Promise<void>" />

Called when a user drops a node onto a valid target folder. The first argument is the moved node and the second is its destination. Direactree does not reorder the tree; update `structure` to apply the move.

```tsx
async function handleNodeMove(source: TreeNode, target: TreeNode) {
  await api.move(source.id, target.id);
  setStructure(await api.fetchTree());
}

<Direactree structure={structure} onNodeMove={handleNodeMove} />;
```

The callback is **not called** when:

- The source is dropped onto itself.
- A folder is dropped into one of its own descendants.
- The destination is a file.
- The destination is already the source's parent.

The target folder opens on drop. While a returned Promise is pending, other drags, saves, and deletes are blocked.

<NodeMoveCallbackDemo />

### Toolbox action callbacks

<ReferenceMeta type="NodePath callbacks" />

```ts
onCreateFolder?: (parentNode: NodePath | null) => void;
onCreateFile?: (parentNode: NodePath | null) => void;
onRename?: (node: NodePath) => void;
onDelete?: (node: NodePath) => void | Promise<void>;
```

- `onCreateFolder` and `onCreateFile` fire when the name editor opens, with the selected parent folder. The folder opens so the editor is visible.
- `onRename` fires when the rename editor opens, with the node being renamed.
- `onDelete` receives the node to delete. With `confirmDelete`, it fires only after the user confirms.

The first three are notifications only. The actual create or rename request arrives through `onSave`. If no node is selected, the create callbacks receive `null`, which means the root.

```tsx
<Direactree
  structure={structure}
  onCreateFolder={(parent) => console.log("Editor open under", parent?.id ?? "root")}
  onRename={(node) => console.log("Renaming", node.id)}
  onSave={handleSave}
  onDelete={handleDelete}
/>
```

### onSave

<ReferenceMeta type="(saveProps: SaveProps) => void | Promise<void>" />

Called when the user confirms a name in the editor, with the Save button or Enter. Escape cancels. Save stays disabled while the name is empty, or unchanged during a rename.

```ts
interface SaveProps {
  newName: string;
  selectedNode: NodePath | null;
  actionType: "create" | "edit";
  createType?: "folder" | "file";
}
```

| Field | Meaning |
| --- | --- |
| `newName` | The value confirmed by the user. |
| `selectedNode` | The parent for a create (`null` for the root), or the node being renamed. |
| `actionType` | `create` for a new node, `edit` for a rename. |
| `createType` | `folder` or `file` during creation; omitted for editing. |

```tsx
function handleSave(change: SaveProps) {
  setStructure((current) => applySave(current, change));
}

<Direactree structure={structure} onSave={handleSave} />;
```

`applySave` is your own code; the [interactive example](/docs/direactree/examples#implementation-notes) has one. A synchronous handler closes the editor right away.

<SaveCallbackDemo />

### Async callbacks and errors

`onSave`, `onDelete`, and `onNodeMove` may return a Promise. Direactree then waits for it:

- While it is pending, the toolbox, the editor, and the confirmation buttons are disabled, and dragging is paused. Only one request runs at a time.
- When it resolves, the editor or confirmation closes.
- When it rejects, or the handler throws, the editor or confirmation stays open with the typed name, and shows the error's `message` (or `messages.actionFailed`). `onActionError` is called with the error and the action.

```ts
type DireactreeMutation = "save" | "delete" | "move";

onActionError?: (error: unknown, action: DireactreeMutation) => void;
```

```tsx
async function handleSave(change: SaveProps) {
  const response = await fetch("/api/tree", {
    method: change.actionType === "create" ? "POST" : "PATCH",
    body: JSON.stringify(change),
  });
  if (!response.ok) throw new Error("The name could not be saved.");
  setStructure(await response.json());
}

<Direactree
  structure={structure}
  onSave={handleSave}
  onActionError={(error, action) => reportError(action, error)}
/>;
```

A failed move has no editor to show the error in, so use `onActionError` to tell the user.

## Complete types

These are the public shapes used by the component:

```ts
interface TreeNode {
  id: string;
  name: string;
  type: "file" | "folder";
  children?: TreeNode[];
  isExpanded?: boolean;
}

type NodePath = {
  name: string;
  id: string;
  type: "file" | "folder";
  parent: NodePath | null;
};

interface SaveProps {
  newName: string;
  selectedNode: NodePath | null;
  actionType: "create" | "edit";
  createType?: "folder" | "file";
}

interface ToolboxIcons {
  createFolder?: React.ReactNode;
  createFile?: React.ReactNode;
  rename?: React.ReactNode;
  delete?: React.ReactNode;
}

type DireactreeTheme = "system" | "light" | "dark";

type DireactreeMutation = "save" | "delete" | "move";

interface DireactreeMessages {
  directoryTree: string;
  createFolder: string;
  createFile: string;
  rename: string;
  delete: string;
  save: string;
  cancel: string;
  newFolderName: string;
  newFileName: string;
  newItemName: string;
  deleteTitle: string;
  deleteFolderDescription: string;
  deleteFileDescription: string;
  deleting: string;
  confirmDelete: string;
  actionFailed: string;
}
```

Import them from the package. `defaultDireactreeMessages` is a value export:

```ts
import Direactree, { defaultDireactreeMessages } from "direactree";
import type {
  DireactreeMessages,
  DireactreeMutation,
  DireactreeProps,
  DireactreeTheme,
  NodePath,
  SaveProps,
  ToolboxIcons,
  TreeNode,
} from "direactree";
```

`direactree/next` exports the same names.
