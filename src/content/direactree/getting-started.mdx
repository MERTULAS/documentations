# Getting started

<p className="lead">Install Direactree, select the correct framework entry point, define a typed structure, and render your first tree.</p>

## Installation

Install the package from npm:

<InstallCommand command="npm install direactree" />

Direactree publishes its TypeScript definitions with the package. You do not need a separate `@types` dependency. It works with React 17 and newer.

### Stylesheet

The component adds its stylesheet from JavaScript. Import it as well when the page should be styled before JavaScript runs, such as with server rendering or static export, or when a Content-Security-Policy blocks styles added by scripts:

```tsx
import "direactree/direactree.css";
```

In a Next.js App Router project, put this import in the root `layout.tsx`.

Useful links:

- [Direactree source repository](https://github.com/MERTULAS/direactree)
- [Direactree package on npm](https://www.npmjs.com/package/direactree)

## Framework imports

### React applications

For a client-rendered React application, use the default entry point:

```tsx
import Direactree from "direactree";
import type { TreeNode } from "direactree";
```

### Next.js 13 and newer

Next.js App Router components are Server Components by default, while Direactree is interactive and must run on the client. There are two supported approaches.

**1. Use the dedicated Next.js entry point—recommended:**

```tsx
import Direactree from "direactree/next";
import type { TreeNode } from "direactree";
```

**2. Use the default entry inside your own Client Component:**

```tsx
"use client";

import Direactree from "direactree";
```

<Callout tone="warning" title="Keep the client boundary focused">
  Put the tree in a small Client Component instead of marking an entire page or layout with `"use client"`. The surrounding content can remain server-rendered.
</Callout>

## Your first tree

The `structure` prop accepts an array of `TreeNode` objects. Every node needs a stable `id`, a visible `name`, and a `type`. Only folders should contain `children`.

```tsx
"use client";

import Direactree from "direactree/next";
import type { TreeNode } from "direactree";

const structure: TreeNode[] = [
  {
    id: "root",
    name: "Project",
    type: "folder",
    children: [
      { id: "readme", name: "README.md", type: "file" },
      {
        id: "src",
        name: "src",
        type: "folder",
        children: [
          { id: "app", name: "App.tsx", type: "file" },
        ],
      },
    ],
  },
];

export function ProjectTree() {
  return (
    <Direactree
      structure={structure}
      isAllExpanded
    />
  );
}
```

The optional `isExpanded` field can control a specific folder's initial state:

```ts
const folder: TreeNode = {
  id: "src",
  name: "src",
  type: "folder",
  isExpanded: true,
  children: [],
};
```

Use stable IDs from your own data source whenever possible. IDs are used to identify nodes across selection, editing, and move operations.

## State ownership

`structure` is controlled: your component owns it, and Direactree only reports what the user asked for. Creating, renaming, deleting, or moving a node calls your handler. The tree changes when you pass a new `structure`.

```tsx
const [structure, setStructure] = useState<TreeNode[]>(initialStructure);
const [selectedNode, setSelectedNode] = useState<NodePath | null>(null);

return (
  <Direactree
    structure={structure}
    onSelectedNodeChange={setSelectedNode}
    onSave={(change) => setStructure((current) => applySave(current, change))}
    onDelete={(node) => setStructure((current) => removeNode(current, node.id))}
    onNodeMove={(node, target) =>
      setStructure((current) => moveNode(current, node.id, target.id))
    }
  />
);
```

`applySave`, `removeNode`, and `moveNode` are your own helpers. The [interactive example](/docs/direactree/examples#implementation-notes) shows them.

The toolbox only enables what you handle. Without `onSave`, create and rename are disabled. Without `onDelete`, delete is disabled. Without `onNodeMove`, nodes cannot be dragged.

`onCreateFolder`, `onCreateFile`, and `onRename` only mean that the name editor opened. The create or rename itself arrives in `onSave` after the user confirms. Return a Promise from `onSave`, `onDelete`, or `onNodeMove` to make the tree wait for your API. See [Props & callbacks](/docs/direactree/api-reference#async-callbacks-and-errors).

## Upgrading from 0.1

Version 0.2 changes some behavior:

- **Handlers enable the controls.** Toolbox buttons and dragging are disabled when the matching handler is missing. A read-only tree needs no extra props.
- **`isAllExpanded` is live.** While `true`, every folder stays open. Setting it to `false` closes every folder. A `key` to remount the tree is no longer needed.
- **Selection follows `structure`.** When the selected node is removed, selection is cleared and `onSelectedNodeChange(null)` is called. A rename or move calls it again with the new path.
- **The styles use CSS variables.** Overrides that targeted internal class names should set `--direactree-*` variables instead. See [Theming](/docs/direactree/theming#css-variables).

New in 0.2: `theme`, `style`, `confirmDelete`, `messages`, `onActionError`, Promise-returning callbacks, keyboard navigation, and the `direactree/direactree.css` export.
