## Why Direactree

Use Direactree anywhere users need to inspect or manage hierarchical data:

- File managers and IDE-style project explorers
- Content management systems and media libraries
- Category, menu, and organization editors
- Database-backed folder structures
- Read-only directory previews

The component is intentionally persistence-agnostic. It accepts a serializable tree and reports user intent through callbacks, so the same UI can work with local React state, a REST API, or another backend.

## How it works

Direactree separates presentation from data ownership:

```text
Your TreeNode[]
      ↓
  <Direactree />
      ↓
selection / create / rename / delete / move events
      ↓
Your state manager or API
      ↓
Updated TreeNode[]
```

1. Pass a `TreeNode[]` to `structure`.
2. Direactree renders the hierarchy and handles its editing interface.
3. Callback props describe what the user selected or attempted to change.
4. Your application updates state or persists the operation, then passes the new `structure`.

Direactree never changes `structure` itself. If a callback returns a Promise, the tree shows the request as pending and waits for it. If the Promise rejects, the editor stays open and shows the error.

<Callout title="Your application stays in control">
  Direactree does not choose a database or API design. You decide how callback payloads are validated, saved, and returned as the next structure.
</Callout>

## Core features

- Create a folder at the root or inside any folder.
- Create a file at the root or inside any folder.
- Rename an existing file or folder.
- Delete an existing file or folder.
- Move nodes with drag and drop.
- Observe the current selection as a complete parent path.
- Ask for confirmation before a delete.
- Wait for async saves, deletes, and moves, with pending and error states.
- Use the built-in toolbox or provide custom icons.
- Configure indentation, expansion, dragging, and sticky controls.
- Pick a light, dark, or system theme, or restyle it with CSS variables.
- Replace every label and message, for translation or your own wording.
- Navigate with the keyboard; screen readers get the ARIA tree roles.
- Use the dedicated Next.js client entry point.

Each toolbox action and dragging is enabled only when you pass its handler. The toolbox can also be hidden independently from drag and drop. This makes read-only trees, partially editable trees, and fully editable explorers possible with the same component.

## Safety guarantees

Direactree rejects structural operations that would create an invalid tree:

- A file or folder cannot be moved into itself.
- A folder cannot be moved into one of its descendants.
- A file cannot receive child nodes.
- Create operations cannot target a file node.
- A node cannot be moved into the folder it is already in.
- `onNodeMove` is not called for an invalid destination.
- Only one save, delete, or move runs at a time.

<Callout tone="success" title="Validation before callbacks">
  Invalid drag destinations are filtered by the component, so `onNodeMove` represents a structurally valid move request. Business rules specific to your application should still be validated in your own handler.
</Callout>
